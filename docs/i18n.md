# Localisation (Part 2.42)

The app ships English and Korean. `src/i18n/strings.ts` holds two flat,
dot-namespaced dictionaries keyed by the same `StringKey` union, so a missing
Korean entry is a **type error**, not a silent fallback at runtime.

## Using it

```tsx
import { useT } from '../i18n'

const t = useT()
t('menu.playVsAi')                    // "AI와 대전"
t('menu.cardsLoaded', { n: 1451 })    // "카드 1451장 불러옴"
```

`{name}` placeholders are substituted from the second argument; an unmatched
placeholder is left in place rather than blanked.

`useLocale()` returns `{ locale, setLocale, t }` when a component needs the
active locale itself (the language toggle, and `TileBadge`, which clips English
type names to fit but shows Korean ones whole).

The provider is mounted once in `src/main.tsx`. It persists the choice to
`localStorage['rb-locale']`, falls back to `navigator.language`, and stamps
`<html lang>` — which drives two `:root[lang='ko']` rules in `index.css` that
relax the HUD's uppercase tracking (Hangul is full-width, so 0.12em tracking
just pulls syllables apart) and bump 10px labels to 11px. The body font stack
also gains Malgun Gothic / Apple SD Gothic Neo / Noto Sans KR after the mono
faces, none of which carry Hangul.

## Glossary (`data/glossary.ko.ts`)

All 39 keyword / game-action / rules-term entries are translated, plus the
`:rb_*:` symbol hover text. The file is `Record<GlossaryKey, …>` keyed to
`GLOSSARY`, so a missing entry is a compile error, and `koFor(entry)` resolves
by **object identity** rather than by matching term text — the lookups all hand
back the very objects in `GLOSSARY`, so it cannot drift.

**Keyword names stay English on screen.** `Deflect 2` is what is printed on the
card and on the card art this app displays, so it is the reader's anchor; the
Korean gloss sits beside it (`굴절 X (Deflect X) — …`) in the hover tooltip and
in the glossary modal. The modal shows the Korean rule as the body with the
English original dimmed underneath, and its search matches both languages.

## Card rules text (`i18n/cardText.ts`)

A **template translator**, not a general one. Riftbound rules text is written
from a small grammar, so an ordered rule list over clause shapes covers a good
part of it; anything unmatched is **left in English** rather than guessed.

Measured coverage against the 235-card fixture pool, in two independent halves:

| | covered | floor in `cardText.test.ts` |
|---|---|---|
| **Prose sentences** | 71% | 69% |
| **Reminder parentheticals** | 100% | 100% |
| overall | 81% | — |

*Neutral* segments (`[Reaction]`, `[Empower] :rb_energy_2:`, `[NO TEXT]` — nothing
to translate) are excluded from both denominators.

**Reminder text** is the rules blurb a card prints for a keyword it carries —
"[Action] (Play on your turn or in showdowns.)". It used to be *dropped* from the
Korean line on the grounds that the glossary already glosses the keyword, which
left a Korean reader with nothing where an English reader gets the rules
explained — and it is a third of everything printed on the cards (133 of 397
sentences). It is also the easiest third: it is boilerplate, the same wording on
every card carrying the keyword, so `REMINDERS` is a lookup table rather than
grammar and 50 shapes cover the whole pool. A reminder with no rule is still
dropped rather than shown in English, so the Korean line never goes half-English.

The uncovered prose is the long tail — 77 sentences in 72 shapes, nearly all of
them appearing once: battlefield statics with nested conditions ("Players ignore
[Deflect] while paying for spells and abilities choosing something here"). Adding
rules is cheap and safe — see `EFFECTS`, `WRAPPERS`, `TRIGGERS`, `TARGETS`.

```
npx tsx scripts/i18n-misses.mts 40
```

ranks what is still missing by how often it appears, so the next batch is aimed
at real cards rather than at whatever is easiest to write.

**Two traps when writing a rule**, both of which produced dead code before they
were found:

- `normaliseNumbers` rewrites number *words* to digits ("one" → "1") before any
  rule runs, so a pattern spelled `/choose one/` can never match. Write
  `/choose (?:one|1)/`.
- `translateSentence` peels a leading `[Keyword]` run and translates the
  remainder. It falls through when that fails, so a rule may match the whole
  sentence including its keyword — but order matters in `EFFECTS` and
  `REMINDERS`: the first *matching* rule that returns non-null wins, so a
  specific wording must sit above the generic one that would also match it.

Two things pass through untranslated even inside a translated sentence:
`[Keyword]` brackets (as above) and `:rb_*:` symbol tokens, so `GlossaryText`
still renders and explains them.

Korean grammar is handled properly rather than by string surgery: `VERBS` is a
table of every verb the rules can emit in plain / "can" / "and" form (trimming
`니다` produces nonsense like `줍수 있습니다`), and particles are chosen by
batchim, including for digits read aloud (`+2를` but `+1을`).

`CardRulesText` (in `GlossaryText.tsx`) is what components render: English as-is
in `en`, and in `ko` the Korean line with the **English original kept beneath it,
dimmed**. Nothing is ever lost, and a rules dispute stays settleable against the
printed wording. It also decodes the HTML entities (`&quot;`, `&gt;`) the card
API returns, which previously rendered literally in both languages.

## Activity log (`i18n/logText.ts`)

Same template approach, applied to the rendered log line rather than the ~140
`appendLog(...)` call sites — which avoids an engine refactor *and* avoids
rewriting the ~20 tests that assert on log substrings. Because these lines are
**engine-authored from a fixed vocabulary** (110 templates, ~47 shapes once card
names and digits are generalised), coverage is effectively complete; the test
holds a floor at 97% and fails when a new `appendLog` shape needs a rule.

Used by `LogLine` (which still colours the actor), the AI recap in
`BriefingPanel`, the live AI narration pill, and `showdownSummaryKo` for the
combat readout. Card names pass through in English.

Particles are resolved wherever they're decidable — after a Korean word or a
digit — via `i18n/korean.ts`. After an English card name they stay as `을(를)`,
which is the standard convention for foreign proper nouns: "Cleave"
transliterates to 클리브 (no 받침 → 를) but "Stacked Deck" ends in 덱 (받침 → 을),
and nothing in the Latin spelling distinguishes them. Note also that 나 + 가
contracts to **내가**, so `side()` returns a ready-made subject form.

## What is deliberately **not** translated

- **Card names.** Riftbound has official Korean printings; inventing names would
  show players something that doesn't match the cards in their hands. Flavour
  text is left alone for the same reason (and it carries no rules meaning).
- **Engine ability labels** (`ab.label` on the legend / gear power buttons) and
  `TargetSpec.label` ("to deal 3 damage"), which the text→script compiler
  derives from card text. Same reason as the log: they are generated English.
  The target *kind* ("an enemy unit") **is** translated, via `targetKindKey`
  in `GameBoard.tsx` — `targetKindLabel` in the engine is now UI-unused.

## Adding a language

1. Add the code to the `Locale` union and `LOCALES` in `strings.ts`.
2. Add a `Record<StringKey, string>` for it and register it in `DICTIONARIES`.
   TypeScript will list every key you still owe.
3. If the script needs different typography, add a `:root[lang='xx']` block
   beside the Korean one in `index.css`.
